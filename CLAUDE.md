# Hockey Tryout Evaluation App — Build Instructions for Claude Code

Copy this whole file into a new empty folder as `CLAUDE.md`, open Claude Code in that folder, and start with the prompt in **Section 9**. Everything above Section 9 is the spec Claude Code should read before writing any code.

---

## 1. What we are building

A mobile-first web app that lets 3–6 volunteer evaluators score hockey players during association tryouts from a phone or iPad standing at the glass or on the bench, and lets one admin (the convenor) see combined rankings and export results.

**Non-negotiable rules**

1. **Players are identified only by pinnie colour + number** (e.g. `W-14`, `B-07`). The app must never store, display, or accept a player's name, birthdate, photo, or parent contact anywhere — not in a field, not in notes, not in a filename. The registrar keeps the number-to-name mapping offline in their own spreadsheet. The app has no knowledge of it.
2. Evaluators only ever see their own scores. They cannot see other evaluators' scores or the combined ranking.
3. The admin sees everything, but still by number only.
4. Must work with flaky rink Wi-Fi: scores are saved locally first and synced when a connection exists. Nothing an evaluator taps can be lost.
5. Scoring must be fast: one player, one category, one tap. An evaluator should be able to score a player on all categories in under 20 seconds without looking away from the ice for long.

## 2. Stack (do not substitute)

| Layer | Choice |
|---|---|
| Front end | Vanilla HTML/CSS/JS, no framework, no build step. ES modules loaded directly. |
| API | AWS AppSync (GraphQL) with JavaScript (APPSYNC_JS) resolvers — no Lambda in the hot path |
| Database | DynamoDB, on-demand billing |
| Auth | Amazon Cognito User Pool. Evaluators and admin sign in with email + password. Groups: `admin`, `evaluator`. |
| Hosting | Static site in S3 behind CloudFront (OAC, HTTPS only) |
| Exports | CSV generated client-side by the admin page; optional copy written to a private S3 bucket via presigned URL |
| Infra as code | AWS CDK v2 in **JavaScript** (not TypeScript), single stack, `cdk deploy` from the repo |
| Region | `ca-central-1` |

Front-end talks to Cognito using `amazon-cognito-identity-js` loaded from a CDN (or vendored into `/web/vendor/`) and to AppSync using plain `fetch` with the Cognito ID token in the `Authorization` header. Do not pull in the full Amplify library.

## 4. Data model (DynamoDB, single table `TryoutTable`)

Use a single-table design with `PK` / `SK` and one GSI.

| Entity | PK | SK | Attributes |
|---|---|---|---|
| Tryout | `TRYOUT#<tryoutId>` | `META` | `name` ("2026-27 U13 Rep B"), `season`, `status` (open/closed), `createdAt` |
| Session (one ice time) | `TRYOUT#<tryoutId>` | `SESSION#<sessionId>` | `label` ("Skate 2 – Scrimmage"), `date`, `type` (skills / scrimmage / game), `order` |
| Player | `TRYOUT#<tryoutId>` | `PLAYER#<playerNumber>` | `playerNumber` ("W-14"), `colour`, `number`, `position` (F / D / G), `active` (bool — set false if the player is released or withdraws) |
| Evaluation | `EVAL#<tryoutId>#<sessionId>#<evaluatorSub>` | `PLAYER#<playerNumber>` | `scores` (map of criterionKey → 1–5), `tier` (A / B / C / X), `notes` (string, ≤ 280 chars), `updatedAt`, `clientId` (for idempotency) |
| Evaluator profile | `USER#<cognitoSub>` | `META` | `displayName` ("Evaluator 3"), `role` |

GSI1: `GSI1PK = TRYOUT#<tryoutId>#PLAYER#<playerNumber>`, `GSI1SK = SESSION#<sessionId>#EVAL#<evaluatorSub>` — lets the admin pull every evaluation for one player across all sessions and evaluators in one query.

Evaluations are **upserts**. Re-scoring a player in the same session by the same evaluator overwrites the previous scores; keep an `updatedAt`. Do not keep history per tap.

## 6. Screens

### 6.1 `index.html` — Login
Email + password, Cognito. On success, route by group: `admin` → admin.html, `evaluator` → evaluate.html. Show first-login "set new password" flow (Cognito temporary password). Remember session in localStorage (wrap every storage call in try/catch — iOS Safari in private mode throws).

### 6.2 `evaluate.html` — Evaluator screen (the important one)

Layout, top to bottom, sized for a phone held in one hand:

1. **Header bar**: tryout name, session picker (dropdown of sessions, defaults to today's), sync status dot (green = all synced, amber = N queued, red = offline), sign out.
2. **Filter chips**: `All` · `White` · `Blue` · `Red` … (one per pinnie colour in this tryout) · `F` · `D` · `G`. Tapping narrows the player grid.
3. **Player grid**: big square buttons, one per active player, showing colour swatch + number + position letter. Button shows a subtle checkmark once the evaluator has scored that player in this session, and a tier letter badge if set. Sort by colour then number.
4. **Scoring sheet** (slides up when a player is tapped):
   - Player number huge at the top (e.g. "W-14 · D").
   - One row per criterion that applies to that position. Each row: label on the left, five big tap targets `1 2 3 4 5` on the right (min 44×44px each). Long-press a number or the label to see the anchor text from `SCALE` / `help`.
   - Tier selector: four buttons A / B / C / X.
   - Notes: single text field, 280 char limit, placeholder "What did you see? (no names)". Client-side: reject anything that looks like a name is impossible to do reliably, so instead show the reminder text and keep the field short.
   - Buttons: **Save & Next** (saves, advances to the next unscored player in the current filter), **Save & Close**, **Clear**.
   - Every tap on a score autosaves to the local queue immediately; Save just closes the sheet. Nothing is lost if the phone locks.
5. **Progress line** at the bottom: "14 of 38 scored this session".

Design notes: high contrast, large text, works in landscape on an iPad too. No hover states. Test with `prefers-color-scheme: dark`. Rink lighting is harsh — avoid low-contrast greys.

### 6.3 `admin.html` — Convenor dashboard

Tabs:

- **Setup**: create/edit tryout; add sessions; add players by pasting a CSV (`colour,number,position`) or one at a time; mark players inactive (released); create evaluator accounts (calls Cognito AdminCreateUser through an AppSync mutation backed by a small Lambda — this is the one allowed Lambda).
- **Rankings**: table of all active players, one row each, columns: number, position, number of evaluations received, weighted average per criterion, overall weighted score, tier votes (A/B/C/X counts), spread (standard deviation of overall across evaluators — highlight rows with high disagreement). Sortable by any column. Filter by position and by session (single session or all sessions combined). Toggle: "equal weights" vs "rubric weights".
- **By evaluator**: pick an evaluator, see their scores, and their average score given across all players (to spot a harsh or generous evaluator; show each evaluator's mean and std-dev next to the group mean so the convenor can normalise mentally, and optionally apply a z-score normalisation toggle to the rankings).
- **Export**: download CSV of rankings and CSV of raw evaluations. Both by player number only. Optional "Upload to S3" button that PUTs the CSV to the private exports bucket via a presigned URL from an AppSync mutation.
- **Close tryout**: sets status closed; evaluators get a read-only view of their own scores.

## 7. GraphQL API (`infra/schema.graphql`)

Auth: Cognito User Pools as the default mode. Use `@aws_auth(cognito_groups: ["admin"])` on admin-only fields.

```graphql
type Tryout { id: ID!, name: String!, season: String!, status: String!, sessions: [Session!]!, players: [Player!]! }
type Session { id: ID!, label: String!, date: AWSDate!, type: String!, order: Int! }
type Player { playerNumber: ID!, colour: String!, number: Int!, position: String!, active: Boolean! }
type Evaluation { playerNumber: ID!, sessionId: ID!, evaluatorId: ID!, scores: AWSJSON!, tier: String, notes: String, updatedAt: AWSDateTime! }
type EvaluatorProfile { id: ID!, displayName: String!, role: String! }

type Query {
  currentTryout: Tryout
  myEvaluations(tryoutId: ID!, sessionId: ID!): [Evaluation!]!
  allEvaluations(tryoutId: ID!): [Evaluation!]!            # admin only
  evaluators: [EvaluatorProfile!]!                          # admin only
}

type Mutation {
  upsertEvaluation(tryoutId: ID!, sessionId: ID!, playerNumber: ID!, scores: AWSJSON!, tier: String, notes: String, clientId: ID!): Evaluation!
  createTryout(name: String!, season: String!): Tryout!     # admin only
  addSession(tryoutId: ID!, label: String!, date: AWSDate!, type: String!): Session!
  upsertPlayers(tryoutId: ID!, players: [PlayerInput!]!): [Player!]!
  setPlayerActive(tryoutId: ID!, playerNumber: ID!, active: Boolean!): Player!
  createEvaluator(email: AWSEmail!, displayName: String!): EvaluatorProfile!   # admin only, Lambda-backed
  closeTryout(tryoutId: ID!): Tryout!
  exportUrl(tryoutId: ID!, filename: String!): AWSURL!      # admin only, presigned PUT
}
```

Resolver rules:
- `upsertEvaluation` **must** take `evaluatorId` from `ctx.identity.sub`, never from the client. Reject writes if the tryout is closed.
- `myEvaluations` filters by `ctx.identity.sub`. An evaluator can never read another evaluator's rows.
- Validate `scores` keys against the criteria list for the player's position; strip unknown keys. Validate values are integers 1–5. Cap `notes` at 280 chars.
- Never accept or return any field that could carry a name. There is no `name` field anywhere in the schema, on purpose. Do not add one.

## 8. Offline queue (`web/js/api.js`)

- Every mutation goes into an IndexedDB store `outbox` first (fall back to localStorage if IndexedDB throws), then the app tries to send it.
- On `online` event, on page load, and every 30 seconds, flush the outbox in order. Use the `clientId` (UUID per player-per-session-per-evaluator, stable across retries) so replays are idempotent server-side.
- If a token has expired while offline, refresh with the Cognito refresh token before flushing; if refresh fails, keep the outbox and prompt to sign in again — do not drop queued items.
- Show queued count in the header. Show a blocking warning if the user tries to sign out with items still queued.

## 10. Definition of done

- `node --test` passes.
- `cdk synth` and `cdk deploy` succeed from a clean clone with only AWS credentials set.
- An evaluator can score a full session on an iPhone with the Wi-Fi turned off, then turn it on and see the sync dot go green.
- The admin rankings CSV contains no column that could hold a name.
- Monthly AWS cost for one association's tryouts (≈ 6 evaluators, 60 players, 8 sessions) is well under $5.
